# 업그레이드 가이드

[English](upgrading.md)

## 공통 절차

| 설치 방식 | 업그레이드 방법 |
|---|---|
| 한 줄 설치(Docker·Podman) | 설치 폴더에서 `scripts/upgrade.sh <버전>`. 예: `scripts/upgrade.sh 0.5.0` |
| 오프라인 번들 | 새 번들을 풀고 `sh pagehouse-<버전>/install.sh --dir <설치 폴더>` |
| 쿠버네티스(Helm) | `helm upgrade <이름> pagehouse-<버전>.tgz -n <네임스페이스> --reuse-values` |

**업그레이드 스크립트가 하는 일:**
1. 지금 상태를 먼저 백업합니다(`backups/before-upgrade/`).
2. `docker-compose.yml`, `.env.example`, 스크립트, 문서를 새 버전으로 바꿉니다.
3. `.env`와 데이터(DB·첨부 볼륨, 백업)는 건드리지 않습니다. 새 설정 항목은 `.env`에 없으면 기본값으로 동작하므로, 필요한 것만 `.env.example`을 보고 옮겨 적으세요.
4. 새 이미지로 다시 띄웁니다. DB 변경(마이그레이션)은 앱이 시작할 때 자동으로 적용됩니다.

**확인:** `curl localhost:<포트>/healthz`에서 새 버전 번호가 보이면 끝입니다.

**되돌리기:**
- 마이그레이션은 앞으로만 적용되므로, 이전 버전 이미지를 그냥 다시 띄우면 안 됩니다.
- 되돌리려면 업그레이드 직전 백업으로 복원합니다.
  ```sh
  scripts/restore.sh backups/before-upgrade/<파일>
  ```
- 그다음 `.env`의 `PAGEHOUSE_VERSION`을 이전 버전으로 바꾸고 `docker compose up -d`로 다시 띄웁니다.

**건너뛰기:** 중간 버전을 건너뛰어도 됩니다. 마이그레이션은 빠진 것부터 순서대로 모두 적용됩니다. 다만 아래에서 **건너뛴 버전들의 확인 사항을 모두** 읽어 보세요.

## 버전별 확인 사항

### 0.4.0 → 0.5.0

DB 변경은 자동으로 적용됩니다. 아래 로그인 유지 기간 변경을 확인하세요(30일을 유지하려면 `SESSION_HOURS=720`). 바뀌는 점:
- **API 토큰에 만료가 생깁니다.** 새 토큰은 30일, 90일(기본), 365일 중에서 고릅니다. 이 버전 전에 만든 토큰은 폐기할 때까지 그대로 동작합니다. SSO로 로그인하는 사람의 토큰은 30일 동안 SSO 로그인이 없으면 멈춥니다(`TOKEN_SSO_GRACE_DAYS`).
- **SSO 그룹 동기화.** 로그인할 때마다 SSO의 `groups` 클레임(`OIDC_GROUPS_CLAIM`)을 위키 그룹으로 맞추고, 없는 그룹은 만듭니다. 직접 넣은 구성원은 그대로입니다. 관리자 그룹(`OIDC_ADMIN_GROUP` 또는 관리 → SSO)을 정하면 그 구성원은 관리자가 됩니다. 클레임을 보내지 않는 SSO 서비스라면 바뀌는 것이 없습니다. [SSO 가이드](sso.ko.md#그룹과-관리자) 참고.
- **SSO가 ID 토큰을 확인합니다**(issuer, audience, 만료, 로그인마다 만드는 nonce). OpenID Connect를 따르는 서비스라면 따로 바꿀 것이 없습니다.
- **웹훅 재시도가 재시작에도 유지되고** 1분, 4분, 16분, 64분 뒤에 다시 보냅니다. 요청에 `X-Event`, `X-Signature` 헤더도 붙습니다(`X-Pagehouse-Event`, `X-Pagehouse-Signature`와 같은 값이고 기존 헤더도 그대로).
- **한글 두 글자 검색**("배포", "장애")이 색인을 탑니다. 업그레이드 때 색인을 한 번 만들므로 문서가 많으면 시작이 조금 늦을 수 있습니다.
- **새로 설치하면** 첫 계정을 만들 때 설치 토큰을 묻습니다(로그에 출력되거나 `SETUP_TOKEN`).
- **SSO가 계정을 SSO 서버의 사용자 ID(`sub`)로 찾습니다.** 기존 계정은 다음 SSO 로그인 때 전처럼 확인된 이메일로 연결되고, 그 뒤로는 SSO 서버에서 이메일이 바뀌어도 같은 계정으로 로그인됩니다(위키의 이메일은 바뀌지 않습니다). 같은 이메일 계정이 이미 다른 SSO 사용자에 연결돼 있으면 거부합니다. 계정 연결과 생성에는 전처럼 확인된 이메일이 필요합니다.
- **계정 테이블이 별도 스키마로 옮겨집니다.** 처음 시작할 때 `users`, `sessions`, `groups`, `group_members`가 데이터와 함께 `public`에서 `accounts`로 옮겨지고, SSO 설정은 `accounts.settings`로 옮겨집니다. 사용할 때 달라지는 것은 없으며, 이 구조 덕분에 [Taskhouse와 계정을 공유](install.ko.md#taskhouse와-함께-쓰기)할 수 있습니다. DB 계정에 데이터베이스의 `CREATE` 권한이 있어야 합니다(데이터베이스 소유자에게는 이미 있습니다). 없으면 앱이 처음 시작할 때 `permission denied for database` 오류로 멈춥니다. 앱 인스턴스가 여러 개면 새 버전이 하나라도 시작한 뒤에는 이전 버전 인스턴스가 동작하지 않으므로, 업그레이드 전에 모두 멈추세요. 직접 실행하는 SQL에는 스키마를 붙여야 합니다(`accounts.users`). 앱은 접속할 때 `search_path`를 지정하므로, 앞에 커넥션 풀러가 있으면 `options` 시작 매개변수를 그대로 넘겨야 합니다. 이전 버전은 새 구조를 읽지 못합니다. 되돌리려면 업그레이드 전에 만든 백업을 복원하세요.
- **로그인 유지 기본값이 30일에서 1일로 바뀝니다.** 매일 다시 로그인하게 됩니다. 전처럼 쓰려면 `.env`에 `SESSION_HOURS=720`을 넣으세요. 업그레이드 전에 로그인한 세션은 원래 만료 시각을 그대로 씁니다.

버그 수정만 있습니다. DB와 설정은 바뀌지 않습니다.

### 0.2.0-beta.3 → 0.2.0-beta.4

- DB 변경: 마이그레이션 `023`(웹훅)이 시작할 때 자동으로 적용됩니다. 나머지 설정은 기존 `settings` 테이블에 저장됩니다.
- **SSO를 관리 화면(관리 → SSO)에서 설정**할 수 있습니다. 저장하면 재시작 없이 바로 적용됩니다.
- `.env`로 SSO를 이미 쓰고 있다면 그대로 동작합니다. 환경 변수가 화면 설정보다 우선하고, 화면은 읽기 전용으로 보입니다. 화면에서 관리하려면 `.env`의 `OIDC_*` 항목을 지우고 같은 값을 화면에 넣으세요.
- **위키에서 로그아웃하면 SSO 서버에서도 로그아웃됩니다.** SSO 서버에 `/`로 끝나는 위키 주소를 로그아웃 후 리디렉션 주소로 허용해 두세요(Keycloak: *Valid post logout redirect URIs*). 허용하지 않으면 SSO 서버가 위키로 돌려보내지 않습니다. 업그레이드 전에 로그인한 사람은 한 번 다시 로그인해야 적용됩니다. 자세한 내용은 [SSO 연결 가이드](sso.ko.md).
- **`.env`에 `SECRET_KEY`가 새로 생깁니다**(업그레이드 때 자동 추가). DB에 저장하는 SSO Client secret을 이 키로 암호화하고, 이미 저장돼 있던 시크릿은 다음에 읽을 때 암호화됩니다. 백업에는 키가 들어가지 않으니 `.env`를 따로 보관하세요. 직접 설치하거나 Helm으로 설치했다면 `openssl rand -hex 32` 같은 긴 무작위 값을 직접 넣으세요.
- **관리 → 개요에 백업 정책이 생겼습니다.** 백업 주기, 자동 백업 보관 개수, 그리고 수동·업그레이드 전 백업까지 며칠 지나면 지울지 정할 수 있습니다. `BACKUP_INTERVAL_HOURS` / `BACKUP_KEEP`는 기본값으로 계속 쓰입니다. compose 파일이 바뀌어 업그레이드 때 백업 컨테이너가 다시 만들어지고, 그때 백업이 한 번 바로 생깁니다.
- **웹훅이 생겼습니다**(마이그레이션 `023`). 관리 → 웹훅에서 페이지·댓글 이벤트를 서명된 JSON으로 보낼 수 있고, 각자 설정에서 자기 알림을 채팅 웹훅으로 받을 수 있습니다. 개인 웹훅은 `WEBHOOK_ALLOW`에 등록한 경우가 아니면 내부망 주소로 보낼 수 없습니다.

### 0.1.0-beta.3 → 0.2.0-beta.1

변경이 큰 버전입니다. 업그레이드 전에 아래를 확인하세요.

**DB 마이그레이션 13개(010~022)가 자동 적용됩니다.** 그룹, 인라인 댓글, 템플릿, 지켜보기·메일, 검색 색인, API 토큰, 공동 편집 상태, 감사 로그, 라벨, 즐겨찾기, 페이지 아이콘, 프로필이 추가됩니다. 기존 데이터는 바뀌지 않고 테이블과 칼럼만 늘어납니다.

**처음 시작할 때:** 검색 색인을 한 번 다시 만듭니다(백그라운드, 페이지 수천 개면 몇 분). 그동안 검색 결과가 조금 덜 정확할 수 있습니다.

**꼭 확인할 설정:**

| 상황 | 할 일 |
|---|---|
| 리버스 프록시(nginx 등) 뒤에서 운영 | **WebSocket을 통과시키도록** 프록시를 설정하세요(실시간 공동 편집). [설치 가이드의 nginx 예시](install.ko.md#https)에 `Upgrade`, `Connection` 헤더와 `proxy_read_timeout`이 있습니다. 안 하면 편집은 되지만 동시 편집 대신 예전 방식 저장으로 동작합니다 |
| 리버스 프록시 뒤에서 운영 | `.env`에 `TRUST_PROXY=1`. 로그인 시도 제한과 감사 로그가 실제 접속 주소를 쓰게 됩니다 |
| SSO(OIDC)를 쓸 예정 | 제공자가 이메일 확인(`email_verified`)을 보내야 로그인됩니다. 안 보내는 제공자(일부 Entra ID)라면 `OIDC_TRUST_EMAIL=1` |
| 비밀번호 재설정 메일을 쓰려면 | `SMTP_URL`, `SMTP_FROM`, `PUBLIC_URL` |
| 쿠버네티스 | 인그레스를 켜면 `TRUST_PROXY=1`이 자동으로 들어갑니다. 인그레스 컨트롤러의 WebSocket 타임아웃을 늘리세요(nginx-ingress: `proxy-read-timeout: "3600"`) |

**동작이 바뀐 것:**
- 관리자가 아니면 페이지를 **제한된 상위 페이지 밖으로 옮길 수 없습니다.** 옮기면 물려받은 열람 제한이 풀리기 때문입니다.
