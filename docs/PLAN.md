# Pagehouse 상세 계획

소규모 회사·팀이 직접 설치해 쓰는 오픈소스 사내 위키. 주간보고, 회의록, 기술 문서를 한곳에서 관리한다.
다른 위키(Confluence, Notion 등)에서 옮겨 오기 쉬워야 한다.

## 1. 원칙

| 원칙 | 구체적 기준 |
|---|---|
| 도입이 간편하다 | `docker compose up -d` 또는 `podman compose up -d` 한 번으로 설치. compose 파일은 두 런타임에서 모두 검증한다. 설정은 `.env` 파일 하나. 첫 접속자가 관리자 계정을 만든다. |
| 백업이 간편하다 | 명령 하나로 DB와 첨부를 묶은 파일 하나가 나온다. 복원도 명령 하나. |
| 확장이 간편하다 | DB는 `DATABASE_URL`만 바꾸면 외부 Postgres로, 첨부는 환경 변수만 바꾸면 S3 호환 저장소로 옮겨진다. |
| 데이터가 갇히지 않는다 | 문서는 ProseMirror JSON으로 저장하고 Markdown으로 내보낼 수 있다. |
| 구성 요소를 늘리지 않는다 | 앱 컨테이너 1개 + Postgres 1개. 검색 엔진·큐·캐시 서버를 따로 두지 않는다. |

## 2. 구성

```
브라우저 ──HTTP/WebSocket──▶ app (Node, 단일 프로세스)
                              ├─ REST API · 정적 화면
                              ├─ 공동 편집 서버 (4단계)
                              └─ MCP 엔드포인트 (5단계)
                                   │
                    ┌──────────────┴──────────────┐
              Postgres 17                  첨부 저장소
              (compose 내장 또는 외부)     (볼륨 또는 S3 호환)
```

- 서버: TypeScript, Hono. 화면: React, Tiptap(ProseMirror).
- 검색: Postgres `pg_trgm`. 한국어 2~3글자 검색어가 동작해야 한다.
- 스키마 변경: 번호 붙은 SQL 파일을 앱이 시작할 때 순서대로 적용한다. 별도 마이그레이션 도구는 쓰지 않는다.
- 설정 값: `DATABASE_URL`, `DATA_DIR`, `PUBLIC_URL`, `ALLOW_SIGNUP`, `S3_*`(선택), `OIDC_*`(선택).

## 3. 현재 상태

0단계와 1단계 완료.

- 계정(첫 가입자가 관리자), 세션 로그인
- 스페이스, 페이지 트리, 하위 페이지 포함 삭제(소프트 삭제)
- 에디터: 제목, 목록, 체크리스트, 표, 코드 블록, 인용, 링크, 이미지·파일 첨부(붙여넣기·끌어놓기)
- 자동 저장, 동시 수정 충돌 감지, 버전 이력과 되돌리기
- 검색
- Postgres, 시작 시 스키마 마이그레이션, `pg_trgm` 검색 색인, `/healthz`
- Dockerfile, compose 파일, `.env.example`. Podman 6.0에서 설치부터 백업·복원까지 확인했다. Docker에서는 아직 확인하지 않았다
- `scripts/backup.sh`, `scripts/restore.sh`
- 서버 테스트 통과(동시 저장 시 한쪽만 성공하는지 포함), 타입 검사 통과. 화면은 브라우저에서 아직 확인하지 않았다

## 4. 단계별 계획

각 단계는 끝나면 그 상태로 쓸 수 있어야 한다.

### 1단계 — 설치·백업 기반 (완료)

| 작업 | 완료 기준 |
|---|---|
| SQLite → Postgres 전환 | 기존 테스트가 Postgres에서 통과 |
| 스키마 마이그레이션 러너 | 빈 DB와 이전 버전 DB 모두에서 시작 시 최신 스키마가 된다 |
| 검색을 `pg_trgm` 색인으로 | "배포" 같은 2글자 검색이 색인을 탄다 |
| `Dockerfile`, `docker-compose.yml`, `.env.example` | 새 장비에서 `docker compose up -d` 후 접속해 첫 계정 생성까지 된다 |
| 백업·복원 명령 | `backup` → 파일 하나 생성, 빈 환경에 `restore` → 페이지·첨부·이력이 동일 |
| 헬스 체크 엔드포인트 | compose와 Kubernetes가 상태를 확인할 수 있다 |

백업 파일은 `pg_dump` 결과와 첨부 디렉터리를 묶은 `tar.gz` 하나다. 주기 실행은 cron 예시를 문서에 싣는다.

### 2단계 — 위키로서 빠진 것 (일부 완료: 페이지 접근 제한(보기·편집, 하위 상속), 초대, 사용자 관리, 비밀번호 변경·재설정, 페이지 이동, 댓글, 템플릿, 휴지통. 남음: 스페이스 단위 권한, SSO, 멘션·알림, 버전 비교, 라벨)

| 작업 | 완료 기준 |
|---|---|
| 권한 | 스페이스별 관리자·편집·읽기 역할, 페이지 단위 열람 제한. 권한 없는 사용자는 API·검색·첨부 어디서도 내용을 볼 수 없다 |
| 사용자 관리 | 관리자가 초대 링크 발급, 역할 변경, 비활성화 |
| 자체 로그인 보강 | 비밀번호 변경·재설정(관리자 발급 링크, 메일 서버 없이도 동작), 로그인 시도 제한, 세션 목록과 강제 로그아웃 |
| SSO (OIDC) | Keycloak·Google·Microsoft Entra·Okta 등 표준 OIDC 제공자 연동. 설정은 `.env`의 `OIDC_ISSUER`·`OIDC_CLIENT_ID`·`OIDC_CLIENT_SECRET` 세 개 |
| 계정 연결 규칙 | SSO 첫 로그인 시 같은 이메일의 기존 계정에 연결하거나 새로 만든다. 허용 이메일 도메인 지정. 관리자가 "SSO만 허용"으로 자체 로그인을 끌 수 있다(관리자 비상 로그인은 남김) |
| 페이지 이동·순서 변경 | 끌어서 다른 상위 페이지나 스페이스로 이동 |
| 댓글 | 페이지 댓글과 답글, 본문 일부에 다는 인라인 댓글, 해결 처리 |
| 멘션과 알림 | `@이름` 입력, 화면 내 알림 목록, 웹훅(Slack 등) |
| 템플릿 | 주간보고·회의록 기본 제공, 팀이 직접 추가 |
| 휴지통 | 삭제한 페이지 목록과 복원 |
| 버전 비교 | 두 버전의 차이를 표시 |
| 라벨, 최근 본 문서, 즐겨찾기 | 사이드바에서 접근 |

### 3단계 — 쓰기 편한 에디터 (일부 완료: `/` 메뉴, 서식 메뉴, 콜아웃, 코드 강조, 표 편집, 목차, Markdown 내보내기, 인쇄. 남음: 접기 블록, Mermaid, 이미지 크기 조절, Markdown 붙여넣기, 페이지 링크 자동완성)

- `/` 명령 메뉴, 선택 시 뜨는 서식 메뉴
- 콜아웃(정보·경고), 접기 블록, 목차
- 코드 블록 언어 선택과 구문 강조, Mermaid 다이어그램
- 표: 셀 병합, 열 너비 조절, 행·열 삭제
- 이미지 크기 조절, 첨부 미리보기
- Markdown 붙여넣기와 Markdown·PDF 내보내기
- 페이지 간 링크 자동완성

### 4단계 — 공개 준비

- README(한국어·영어), 설치·백업·업그레이드 문서
- CI(테스트, 타입 검사, 이미지 빌드), 컨테이너 이미지 공개
- Helm 차트
- 라이선스 Apache-2.0, 기여 안내, 보안 신고 절차
- 보안 점검: 권한 우회, 업로드 파일, 로그인 시도 제한

여기까지가 "플랫폼 완성"이다.

### 5단계 — Confluence·Notion 이관

```
소스 어댑터 ──▶ 중간 포맷(디렉터리) ──▶ 로더
```

| 작업 | 완료 기준 |
|---|---|
| Confluence 어댑터 | REST API v2로 페이지 트리·본문(ADF)·첨부·댓글·폴더·라벨·작성자·작성일을 가져온다 |
| ADF → 문서 변환 | 지원하지 않는 매크로는 원본을 담은 "미지원 블록"으로 남긴다. 내용이 사라지지 않는다 |
| 변환 리포트 | 페이지별로 변환되지 않은 요소 목록이 나온다 |
| 재실행 | 같은 소스를 다시 돌리면 중복 없이 갱신된다 (전환 기간 병행 운영용) |
| 링크 재작성 | 내부 링크는 새 주소로, 옛 Confluence 주소는 리다이렉트 |
| 사용자 매핑 | 이메일 기준, 없는 사용자는 비활성 계정 |
| Notion 어댑터 | 블록 트리 변환, 데이터베이스는 표로 |
| 실데이터 검증 | 사내 스페이스 2개(약 3,100쪽, 첨부 약 9,000개)를 옮겨 변환 리포트와 화면을 확인한다. 이관 도구의 실제 검증 데이터로 쓴다 |

### 6단계 — 공동 편집

- Yjs 기반 실시간 동시 편집, 다른 사람의 커서와 접속자 표시
- 앱 프로세스 안에서 WebSocket으로 동작, 문서 상태는 Postgres에 저장
- 0단계의 충돌 감지는 공동 편집이 꺼진 환경의 대체 수단으로 남긴다

### 7단계 — 에이전트용 API·MCP

- 개인 API 토큰 (사용자 권한을 그대로 따른다)
- MCP 도구: 검색, 페이지 읽기(Markdown), 페이지 생성·수정, 트리 조회, 댓글 작성
- 에이전트가 쓴 변경도 버전 이력에 작성 주체가 남는다

## 5. 확장 경로

| 상황 | 방법 |
|---|---|
| 첨부가 디스크를 채운다 | `S3_*` 설정으로 S3 호환 저장소(MinIO 등)로 전환, 이전 스크립트 제공 |
| DB를 따로 운영하고 싶다 | `DATABASE_URL`을 외부 Postgres로 지정 |
| Kubernetes에 올린다 | Helm 차트 사용 |
| 사용자가 늘어난다 | 앱은 상태를 DB에 두므로 장비 사양을 올리는 것으로 충분하다. 다중 인스턴스는 필요해질 때 다룬다 |

## 6. 하지 않는 것

화이트보드, Notion식 데이터베이스, 플러그인 시스템, 모바일 앱, 사용 통계, 다중 테넌트, SAML.

## 7. 정해야 할 것

없음. 이름은 Pagehouse, SSO는 OIDC만 지원(SAML 제외)으로 정했다.
